# 编译原理 实验五 中间代码优化

### 231220060 侯兴宇

## 一、程序实现的功能

本程序基于老师提供的数据流分析框架，实现了 C-- 中间代码的**全局优化**，包含以下五项优化 pass：

### 1. 全局常量传播 (Constant Propagation)

采用三值 lattice（UNDEF / CONST / NAC）的前向数据流分析。每个变量被映射为三个可能状态：UNDEF（尚未定义）、CONST(c)（确定常数值）、NAC（非常量）。多条控制流路径汇合时，通过 lattice join 合并信息：UNDEF 为幺元，NAC 吸收一切，不同常量值冲突则上浮为 NAC。分析完成后，对每条语句执行**常量折叠**——将引用位置直接替换为常量字面量，暴露出更多优化机会。

### 2. 全局公共子表达式消除 (Common Subexpression Elimination)

预处理阶段（`merge_common_expr`）将每个算术表达式 `x op y` 提取为独立的表达式变量 `expr := x op y`，同时完成**代数简化**（`x+0→x`、`x*1→x`、`x/1→x` 等）。随后通过前向 **Must** 分析求解可用表达式，meet 取交集——只保留在所有前驱路径上都已计算的表达式。最后删除那些表达式变量已可用的冗余计算语句。

### 3. 复制传播 (Copy Propagation)

跟踪 `x := y`（y 为变量）的复制关系，是前向 Must 分析。使用双向映射 `def→use` 和 `use→def` 维护复制对，meet 取交集。转移函数中，任何对 x 的重新定义会 kill 两类复制对：x 作为 def（`x→y` 被打破）和 x 作为 use（`y→x` 因源值变化而失效）。分析后将所有可传播的变量引用替换为其副本源。

### 4. 死代码消除 (Dead Code Elimination)

基于后向活跃变量分析（May 分析，meet 取并集）迭代执行。每轮分析后倒序遍历基本块：若某条 `x := ...` 的 def 变量不在活跃集中，说明该定义的值此后从未被使用，标记为死代码并删除。反复迭代直至不动点，无新的死代码产生。

### 5. 后向数据流求解器

在框架已提供的前向求解器（迭代/worklist）基础上，实现了完整的后向求解器。后向分析与前向构成镜像：边界从 Entry 变为 Exit；OUT[B] 由后继的 IN 汇合得到；worklist 传播方向反转（IN 变化时加入前驱而非后继）。

### 优化流水线编排

以上 pass 按固定顺序对每个函数执行：

```
常量传播(1) → 公共子表达式消除 → 复制传播 → 常量传播(2) → 死代码消除(迭代)
```

第二轮常量传播用于捕获前序 pass 暴露的新常量（如复制传播将变量替换为常量后产生的新常量表达式）；死代码消除放在最后收尾，清理所有 pass 留下的无用赋值。

## 二、编译与运行说明

### 编译

本项目位于 `cmmc_optimizer-main/` 目录下。实验选择了**数据流分析相关优化（task1）**。为适配线上评测平台的可执行文件命名规范，对原始 Makefile 做了调整——直接使用 `make parser` 即可完成编译并生成评测机所需的 `parser` 文件：

```bash
cd cmmc_optimizer-main
make parser
```

该命令实际编译 task1 源码（`make TASK=task1`），随后自动将生成的 `parser_task1` 拷贝为 `parser`，一步到位。

编译依赖 `flex`、`bison` 和 `gcc`，Makefile 中已配置完整的 flex/bison 预处理和 C 编译链接流程。

### 运行

```bash
./parser <input.ir> [output.ir]
```

- 第一个参数为输入 IR 文件的路径（由实验三/四的编译器前端生成）。
- 第二个参数为可选的输出文件路径。
- 程序首先解析输入 IR 文本为内存数据结构，随后调用 `IR_optimize1()` 执行上述优化管道，最后将优化后的 IR 输出。

## 三、实现亮点

### 1. 统一的求解器抽象

所有分析共享同一套 `DataflowAnalysis` 虚函数表接口（`isForward`、`newBoundaryFact`、`newInitialFact`、`meetInto`、`transferBlock`），仅通过按需填充子类方法即可接入 worklist/迭代求解器。前向与后向求解器在代码结构上严格对称，初始化、迭代和 worklist 传播三个阶段均成镜像，降低了理解与调试成本。

### 2. 多风格 Fact 表示的兼容

不同分析的 Fact 差异很大——常量传播用 lattice map、活跃变量用集合、可用表达式和复制传播用带 `is_top` 标志的集合/map。框架通过 `void*` 和虚函数调用实现了多态 Fact 操作，`meetInto` 和 `transferBlock` 内部各自解释，求解器层完全不感知具体类型。

### 3. 迭代式死代码消除

采用"分析-标记-删除-重分析"的循环策略。单轮 LVA 删除一层死代码后，可能暴露出新的死代码（被删除语句的 def 如果不再被任何语句使用，其自身的 use 可能也不再需要），因此反复迭代到不动点才能最大化消除效果。

### 4. 防御性代码设计

在 `simple_expr_optimize` 的代数简化中，使用二级指针 `IR_stmt**` 原地替换语句对象，避免了链表迭代器失效问题；在常量除零场景中返回 UNDEF 而非崩溃，保证了分析的健壮性。
